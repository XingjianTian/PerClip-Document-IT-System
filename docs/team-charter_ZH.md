## （如何沟通和共享信息）

拟议沟通方式：使用私密群聊协调，使用 GitHub issues 或共享行动清单分配工作，通过 pull requests 审查文档。团队须在首次会议上选择聊天平台。群聊中影响范围、预算或截止日期的决策，应复制到决策日志中。

成员应尽可能在 24 小时内确认收到工作请求。威胁截止日期的阻碍事项应于当天提出。组长协调应对；有关课程要求的未决问题，只有在小组同意措辞后，才向授课教师升级反馈。由一名指定代表为全组统一提交一次课程成果。

## 团队目标

为 Task 1 编制内容一致的项目提案和团队章程，为 Task 2 编制完整的项目章程，并开展全体五名成员参与的清晰展示。将 PerClip RAG Document Management System 控制在切实可行的文档管理范围内，后续有关原型的陈述须有实际证据支持。

## 团队价值观

工作透明，尊重成员的可用时间，认可实际贡献。使用清晰的英文术语，以建设性的方式审查工作，区分功能计划、目标和实测结果。

## 团队道德准则

不得捏造访谈、用户测试、支出、开发结果、出勤、协议或签名。使用课程及外部资料时须引用。审查 AI 辅助写作的准确性，遵守适用的大学规定，并在要求时披露所获协助。私密文档和凭据不得进入仓库或录制内容。

## 规则与期望

负责人在内部审查日期前完成草稿；审查者尽可能在 24 小时内提供可执行的反馈。组长检查整合情况，但每名负责人仍对内容准确性负责。只有记录变更对范围、时间、成本和质量的影响后，才能接受变更。争取共识；未解决的分歧须连同选项记录，并在需要时提交授课教师处理。

对于未完成的任务，联系负责人，商定补救日期，仅经小组明确决策后重新分配。记录实际工作，不假定贡献均等。录制前，每人排练自己的部分、核对术语并准备回答问题。合成视频仍以授课教师接受为条件；所有成员均须保持可参加现场问答的状态。
